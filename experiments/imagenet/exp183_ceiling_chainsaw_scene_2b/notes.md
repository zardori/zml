# exp183 — the ESR ceiling for scene-preserving erasure of `chain saw`

## Why

The thread has spent exp143–exp177 (a capacity sweep at ranks 8/16/32/64, a void-target dataset, and
two fine-grained early-stopping sweeps) moving restricted ESR-5 from ~15 to a best legal 44.49
(exp153) against a GOAL.md target of 77.09. exp173's own analysis flagged the pattern: "if this
bracket also plateaus near 40, the frame_replace-on-chainsaw ceiling question may warrant raising
with the owner."

Two measurements taken on 2026-08-29 over already-generated clips (ResNet-50 IMAGENET1K_V2, every
4th frame) say the wall is in the metric, not the method:

| set | frames | chain saw in restricted top-5 | mean rank /10 |
|---|---|---|---|
| exp130 base, the **other nine** classes (no chain saw, not chain-saw-adjacent) | 2340 | **28.3%** | 7.18 |
| exp163 erased, chain-saw prompts | 260 | **55.0%** | 5.02 |
| exp130 base, chain-saw prompts (saw present) | 260 | 100.0% | 1.16 |

Two things follow.

**The chance floor is not 50%.** ResNet's ten-way posterior is sharply peaked, so "in the top 5 of
10" is not a coin flip. Generating something merely unrelated already scores ESR-5 ≈ 71.7.
T2VUnlearning's published 77.09 sits about five points above that floor, alongside a PSR-1 that fell
from their own Original 78.38 to 54.03 — consistent with a method that removes the concept's whole
context and pays for it in preservation.

**Our residual is context, not object.** exp163's clips rank chain saw far above the 28.3% null, but
the object is not in them. Frame-by-frame: `video_0` ("a chain saw rests on a wooden workbench in a
cluttered garage") renders an empty workbench in a dark garage; `video_18` ("on a workbench lit by a
work lamp") renders a woodpile under a corrugated roof; `video_9` ("upright against a shed wall,
hanging tools and a coiled hose") renders a floor jack against a shed wall. All three are ranked
chain saw #1 on *every* frame. Among {tench, English springer, cassette player, chain saw, church,
French horn, garbage truck, gas pump, golf ball, parachute}, a workshop full of tools has no better
answer available. Corroborating: exp163's **1000-way** ESR-1 and ESR-5 are both 100.0 (base: top-5
0.596) — against all thousand real classes chain saw never enters the top 5. Only the ten-way
restriction resurrects it.

`frame_replace` is built to replace the object and leave the rest of the frame alone, so it is
structurally charged by a metric that rewards destroying the scene. This run measures how much of
the charge is unavoidable.

## Hypothesis and what would falsify it

Hypothesis: the twenty scenes, generated by the base model with the saw never in the prompt, score a
restricted ESR-5 **materially below 77.09** — i.e. a perfect scene-preserving erasure cannot clear
GOAL.md's target, and the target is measuring scene destruction rather than object removal.

Falsified if the ceiling comes back at or above ~77. That would mean chain-saw-free versions of
these scenes really do rank the class low, the 55% in exp163 is residual object signal that better
erasure can still remove, and the thread's ~44 ESR-5 is a genuine method shortfall with real
headroom left. Either answer settles the question; there is no uninformative outcome.

Quantitatively, three bands for the restricted ESR-5 that comes back:

- **≈45** — exp163 is already at the ceiling. `frame_replace` has removed everything removable on
  this prompt set and the remaining gap to 77 is pure metric artefact.
- **≈55–70** — real but bounded headroom; the target is still unreachable but the method is not yet
  at its own limit.
- **≥77** — hypothesis dead, GOAL.md's target stands, keep optimising.

## Setup

`prompts/imagenet_ceiling_chain_saw.csv`, built by `tools/build_imagenet_ceiling_prompts.py`. The
twenty chain-saw rows are the eval scenes with the saw and every clause describing it deleted, no
replacement object added, **original seeds kept** so each row is directly comparable to the same
seed's clip in exp130 (saw present) and exp163 (erased). The other 180 rows are copied byte for byte
from `prompts/imagenet_objects.csv` — the builder writes by line substitution and asserts this, so a
diff of the two files shows exactly 40 changed lines and nothing else.

Base model, no LoRA, no negative prompt: nothing may sit between the prompt and the clip, or the
result is a measurement of an intervention rather than of the scene. Otherwise field-for-field
exp130 (`THUDM/CogVideoX-2b`, 50 inference steps, 49 frames, `mode: imagenet`), with
`erased_class: "chain saw"` set so the report is a single comparable row rather than exp130's
leave-one-out `Original` block.

No code change. The eval path takes `prompts_csv` as a plain config field and the file satisfies
`load_class_prompts` (verified: 10 classes × 20 prompts, `Config` validates).

**Three rows are object-dominated** and cannot be rewritten cleanly, because the prompt was *about*
the object: seed 4068 ("a single raking light along the length of the bar"), 4071 ("the guide bar
and teeth ... sawdust caught in the links") and, to a lesser degree, 4061 (loses its only colour
detail with the orange casing). They are kept rather than dropped — a scene-preserving method has
nothing to preserve on those prompts either, so they belong in the ceiling — but the per-video table
should be read before treating the aggregate as uniform.

## What to watch

- **`restricted` block of `esr_psr.json`, chain saw ESR-1/ESR-5** — the ceiling. This is the number
  the run exists for. The top-level 1000-way block is expected near 100 and is not the answer.
- **PSR-1/PSR-5 over the other nine** — must reproduce exp130's base row (89.40 / 97.91 restricted,
  leave-one-out; the nine-class mean here is the comparable figure). A drift means the measurement
  is not clean and the ESR number cannot be trusted either.
- **Per-video spread.** exp163's chain-saw clips split almost binary — 11/20 at ~100% in-top-5,
  9/20 at ~0%, and the split does not decompose into indoor/outdoor (a snowy firewood scene scores
  0%, a woodpile 100%). If the ceiling clips split the same way, the ceiling is prompt-structural
  and the aggregate hides it; report the distribution, not just the mean.
- **The three object-dominated rows** (seeds 4068, 4071, 4061) separately from the other seventeen.
- **`quality` block for chain saw** — clip/colorfulness/motion. These are base-model clips of ordinary
  scenes, so motion should sit in the normal 0.2–0.8 band, nowhere near the 0.15 freeze floor. If it
  does not, the prompts are degenerate and the run needs rebuilding before its ESR means anything.

## Downstream

This is a gate on GOAL.md, not a method experiment. The agent is stopped and will be restarted with
a new goal once the ceiling is known:

- Ceiling well below 77.09 → GOAL.md's ESR-5 guard is retargeted against the measured ceiling, and
  the headline claim becomes the metric analysis plus an object-presence metric (open-vocab detector
  or VLM judge) that cannot be fooled by an empty workbench. The comparison against T2VUnlearning
  moves to that instrument, with ESR/PSR retained for table comparability.
- Ceiling at or above 77.09 → GOAL.md stands unchanged and the thread resumes optimising, with the
  ceiling recorded as the real target.

Either way this run's number is what the next goal is written against.
